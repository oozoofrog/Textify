# Textify 상용 배포 완성도 기획서

- 작성일: 2026-03-14
- 대상 제품: Textify
- 플랫폼: iOS
- 배포 채널: TestFlight, App Store
- 기준 버전: 1.0.0

---

## 1. 문서 목적

본 문서는 Textify를 **개발 완료 수준의 앱**에서 **상용 배포 가능한 제품**으로 끌어올리기 위한 기준, 작업 항목, 일정, 검증 게이트를 정의한다.

핵심 목표는 다음 두 가지다.

1. **TestFlight 배포 가능 상태 확보**
2. **App Store 제출 가능 상태 확보**

즉, 단순히 기능이 동작하는 수준을 넘어서 아래를 모두 만족하는 상태를 목표로 한다.

- 핵심 사용자 플로우 안정성 확보
- 권한/실패/복구 흐름 명확화
- 테스트 및 수동 QA 완료
- 스토어 메타데이터/스크린샷/정책 자산 준비
- 출시 후 대응 가능한 운영 최소 체계 확보

---

## 2. 현재 상태 요약

### 2.1 현재 강점
- 사진 선택 → ASCII 생성 → 복사/공유/저장 → 히스토리 → 설정 흐름이 구현되어 있다.
- SwiftUI + MVVM + Repository 구조가 비교적 명확하다.
- `make build-app`, `make test-app` 기준 로컬 빌드/테스트가 통과한다.
- 권한 거부/제한 상태에 대한 사용자 메시지 흐름이 일부 반영되어 있다.
- App Store 메타데이터 초안 및 릴리즈 체크리스트 문서가 존재한다.

### 2.2 현재 부족한 점
- 상용 배포 기준의 **수동 QA 완료 증빙**이 없다.
- UI 자동화 테스트가 없다.
- 성능 목표 대비 **실측/기록 체계**가 부족하다.
- 스토어 제출 필수 자산(스크린샷, 지원 URL, 개인정보 처리방침 URL)이 미완성이다.
- 배포용 문서/워크플로 일부가 실제 저장소 상태와 완전히 정렬되지 않았다.
- 출시 후 운영 관점(문의 응대, 이슈 triage, 버그 대응 기준)이 아직 약하다.

## 3. 상용 배포 완성도의 정의

Textify의 상용 배포 완성도는 아래 6개 축으로 정의한다.

| 축 | 설명 | 현재 추정 | 목표 |
|---|---|---:|---:|
| 기능 완성도 | MVP 기능 구현 및 흐름 연결 | 85 | 95 |
| 안정성 | 실패/권한/상태 전이/회귀 안정성 | 75 | 90 |
| 테스트 | Unit/UI/수동 QA 체계 | 70 | 90 |
| 스토어 준비 | 메타데이터/스크린샷/정책/아이콘 | 55 | 95 |
| 운영 준비 | 문의/버그 대응/릴리즈 판단 기준 | 45 | 80 |
| 배포 실행성 | 빌드/테스트/제출 절차 명확성 | 65 | 90 |

**상용 배포 가능 판정 기준:**  
위 6개 축 중 어느 하나도 80 미만이면 정식 배포하지 않는다.

## 4. 배포 목표 상태

### 4.1 TestFlight 배포 가능 상태
아래 조건을 모두 만족해야 한다.

- 사진 선택 후 첫 결과 생성이 정상 동작한다.
- 팔레트, 출력 폭, 대비, 밝기 반전이 안정적으로 반영된다.
- 복사, 공유, 저장 3개 액션이 모두 정상 동작한다.
- 히스토리 생성/조회/삭제가 동작한다.
- 권한 `notDetermined / denied / restricted / authorized` 흐름이 확인되었다.
- `make build-app`, `make test-app`가 연속으로 성공한다.
- 크리티컬 버그 0건, 메이저 버그 0건 상태다.

### 4.2 App Store 제출 가능 상태
TestFlight 기준을 만족한 상태에서 아래를 추가로 만족해야 한다.

- 대표 기기에서 portrait/landscape 수동 QA 완료
- App Icon, 스크린샷, 설명문, 키워드, What’s New 확정
- 개인정보 처리방침 URL / Support URL 준비
- 리뷰어 참고 사항 정리
- 제출 빌드 버전/빌드번호 확정
- 출시 후 버그 대응 기준 수립

## 6. 핵심 추진 과제

### 6.1 제품 안정화
목표: 사용자가 가장 자주 밟는 흐름에서 오동작이 없도록 한다.

주요 과제:
- 출력 폭 슬라이더 변경 시 **최종 값 반영 보장**
- 빠른 연속 조작 시 생성 취소/재생성 상태 안정화
- 저장 중 중복 탭 방지 확인
- 공유/저장 실패 메시지 일관화
- 히스토리 중복 기록 정책 점검

완료 기준:
- 재현 가능한 조작 케이스에서 상태 꼬임 없음
- 크래시/멈춤/잘못된 결과 표시 없음

### 6.2 테스트 강화
목표: 회귀 위험을 줄이고 릴리즈 판단 근거를 만든다.

주요 과제:
- `MainViewModel` 테스트 추가
- `HistoryViewModel` 테스트 추가
- 출력 폭/팔레트 변경의 최종 결과 반영 테스트 추가
- 최소 1개 이상 UI smoke test 도입
  - 앱 실행
  - 메인 진입
  - 설정 진입
  - 히스토리 빈 상태 확인

완료 기준:
- 핵심 ViewModel 테스트 보강
- 주요 상태 전이 테스트 보유
- UI smoke test 1~3개 이상 통과

### 6.3 수동 QA 체계화
목표: 실제 사용자 조건에서의 동작을 확인한다.

주요 과제:
- 이미지 샘플 세트 준비
  - 저조도
  - 고대비
  - 인물
  - 풍경
  - 저해상도
  - 고해상도
- 환경별 QA 수행
  - iPhone portrait
  - iPhone landscape
  - Light / Dark Mode
- 예외 상황 QA 수행
  - 이미지 로드 실패
  - 생성 실패 후 재시도
  - 권한 거부 후 설정 이동/복귀
  - 히스토리 없음 상태

완료 기준:
- 체크리스트 전 항목 소거
- 미해결 이슈는 severity와 함께 등록

### 6.4 스토어 자산 준비
목표: App Store 심사 및 전환에 필요한 자산을 완성한다.

주요 과제:
- 앱 설명 / 부제 / 키워드 확정
- What’s New 확정
- 한국어 스크린샷 촬영
- App Icon 최종 확정
- Support URL 준비
- Privacy Policy URL 준비
- 리뷰어 참고 사항 정리

완료 기준:
- App Store Connect에 바로 입력 가능한 텍스트 세트 완성
- 스크린샷 업로드 가능한 파일 세트 준비
- 외부 URL 접근 가능 상태

### 6.5 운영 준비
목표: 출시 후 문제 발생 시 대응 가능한 최소 체계를 만든다.

주요 과제:
- 이슈 라벨 체계 정의
  - crash
  - data-loss
  - permissions
  - ui-bug
  - enhancement
- 버그 severity 기준 정의
- 핫픽스 기준 정의
- 피드백 수집 창구 일원화
- 첫 2주 대응 원칙 수립

완료 기준:
- 출시 직후 대응 프로세스가 문서화됨
- 심각도 기준에 따른 우선순위 판단 가능

## 8. Go / No-Go 기준

### Go
아래를 모두 만족하면 제출 가능:
- `make build-app` 성공
- `make test-app` 성공
- 크리티컬 버그 0
- 메이저 버그 0
- 권한 흐름 검증 완료
- 스토어 자산 준비 완료
- 수동 QA 체크리스트 완료
- Support / Privacy URL 준비 완료

### No-Go
아래 중 하나라도 해당하면 제출 보류:
- 저장/공유/생성 중 핵심 플로우 실패
- 상태 꼬임 또는 재현 가능한 UI 블로킹 존재
- 권한 거부 후 복구 동선 부재
- 스크린샷/메타데이터/정책 URL 미완성
- 대표 기기 수동 QA 미완료

## 12. 성공 기준

상용 배포 성공은 단순 제출이 아니라 아래 상태를 의미한다.

- 사용자가 첫 실행 후 1분 내 첫 ASCII 결과를 만들 수 있다.
- 저장/공유/복사 흐름에서 치명적인 실패가 없다.
- 리뷰어가 앱 목적과 권한 사용 이유를 쉽게 이해할 수 있다.
- 출시 후 1주 내 치명적 수정 없이 운영 가능하다.

---

## 13. 결론

Textify는 현재 **개발 MVP 수준에서는 상당히 완성도가 높지만**, **상용 배포 기준에서는 검증, 자산, 운영 준비가 더 필요하다.**

따라서 다음 전략을 따른다.

- **코드 완성 → 배포 완성**으로 기준을 전환한다.
- 기능 추가보다 **안정화, QA, 스토어 준비**를 우선한다.
- TestFlight를 중간 게이트로 활용하고, App Store 제출은 그 다음 단계로 진행한다.
