# Textify MVP 구현 계획서

- 작성일: 2026-03-13
- 목적: 새 제품 정의와 UI/UX 설계를 기준으로 실제 구현 순서, 테스트 범위, 검증 기준을 고정한다.

---

## 1. 구현 목표

이번 구현은 **기존 `TextifyKit` 코어를 유지하면서**, 앱 엔트리와 작업공간 경험을 다시 정리하는 데 집중한다.

핵심은 다음 4가지다.

1. 홈 진입 경험 정리
2. 작업공간 액션 구조 개선
3. 히스토리/설정 연결
4. 서비스 주입과 테스트 구조 보강

---

## 2. 적용 원칙

- SRP: View는 표시, ViewModel은 상태/흐름, Service는 시스템 작업에 집중
- OOP: 역할이 분명한 타입과 프로토콜 경계 유지
- Pure DI: `AppDependencies`에서 생성하고 주입
- TDD: 상태 전이와 서비스 상호작용을 테스트로 보호
- Swift 6 / iOS 26 유지

---

## 3. 구현 범위

### 3.1 문서 정렬
- `docs/PRODUCT_SPEC.md`
- `docs/MVP_UI_UX_REDESIGN_BRIEF.md`
- `docs/MVP_UI_UX_IMPLEMENTATION_PLAN.md`
- `docs/DEVELOPMENT_DESIGN.md`

### 3.2 앱 구조 정리
- `TextifyApp.swift`가 `AppDependencies`를 루트에서 소유
- `MainView`와 `TextifyView`가 DI된 ViewModel만 사용

### 3.3 홈/작업공간 개선
- 홈에서 최근 작업/설정 진입 가능
- 작업공간에서 복사/공유/저장/옵션 제공
- 저장 및 히스토리 기록 연결

### 3.4 테스트
- `TextifyViewModel`의 생성/취소/debounce 회귀 유지
- 복사/저장/히스토리 저장 흐름 테스트 추가
- 필요한 경우 설정/서비스 프로토콜 목 구현

## 4. 단계별 작업

### Step 1. 문서 소스 오브 트루스 확정
- 제품 정의를 OCR이 아닌 ASCII 앱으로 고정
- iOS 26 기준 반영

### Step 2. Composition Root 정리
- `AppDependencies`에서 메인 흐름에 필요한 모든 의존성 제공

### Step 3. 홈 화면 개선
- CTA 강화
- 보조 시트 연결
- 오류 처리 정리

### Step 4. 작업공간 개선
- 명시적 액션 바 도입
- 옵션 시트 단순화
- 복사/저장/히스토리 저장 연결

### Step 5. 설정/히스토리 보강
- 설정에서 히스토리 삭제 동작 실제 연결
- 홈/작업공간에서 히스토리 접근 경로 제공

### Step 6. 테스트 및 빌드 검증
- `make test-app`
- `make build-app`

---

## 5. 리스크

### 5.1 기존 미연결 플로우와의 중복
`Home`, `ImageSelection`, `Generation`, `Result` 같은 이전 실험적 흐름이 남아 있어 제품 정의가 다시 흐려질 수 있다.

### 5.2 상태 중복
`TextifyViewModel`에 생성/피드백/옵션 상태가 모여 있으므로, 액션 추가 시 책임이 과해지지 않도록 서비스 경계를 유지해야 한다.

### 5.3 히스토리 저장 타이밍
히스토리 저장은 복사/저장 같은 소비 액션 중심으로 제한하고, 중복 저장 방지 로직을 유지한다.

---

## 6. 완료 기준

- 홈에서 사진 선택, 최근 작업, 설정 진입 가능
- 작업공간에서 복사/공유/저장/옵션 동작 가능
- 복사하거나 저장한 결과가 히스토리에 남음
- 설정에서 히스토리 삭제 가능
- 관련 테스트가 통과함
- 빌드가 iOS 26 기준으로 통과함
