# Textify MVP UI/UX 설계 문서

- 작성일: 2026-03-13
- 문서 목적: Textify의 MVP 사용자 경험을 **런치 → 작업공간 → 보조 레이어** 구조로 재정의하고, 구현에 바로 연결할 수 있는 UI 기준을 제공한다.

---

## 1. UX 방향성 요약

**Textify의 핵심 경험은 “사진을 고른 직후 결과가 나오고, 바로 복사하거나 공유하는 것”이다.**

따라서 MVP UX는 다음을 지켜야 한다.

- 첫 행동은 항상 하나여야 한다.
- 옵션보다 결과를 먼저 보여줘야 한다.
- 기능은 많더라도 액션은 쉽게 보여야 한다.
- 텍스트 아트 결과물이 화면의 주인공이어야 한다.

---

## 2. 디자인 원칙

### 2.1 Default First
앱을 처음 실행한 사용자도 설명을 읽지 않고 `사진 선택`만 누르면 시작할 수 있어야 한다.

### 2.2 Result First
작업공간에서는 옵션보다 결과물이 더 큰 비중을 가져야 한다.

### 2.3 Visible Actions
복사/공유/저장 같은 핵심 액션은 아이콘만 있는 숨은 툴바가 아니라, **명시적 액션 바**로 노출한다.

### 2.4 Advanced on Demand
옵션은 하단 시트에 모아 기본 흐름을 방해하지 않게 한다.

### 2.5 Quiet Premium
배경과 장식은 결과물을 돋보이게 하는 수준에서만 사용한다.

---

## 3. 화면 구조

## 3.1 런치 화면 (`MainView`)

### 목표
- 앱이 무엇을 하는지 즉시 이해시킨다.
- 가장 빠르게 첫 결과로 유도한다.

### 구성
- 배경: 저대비 텍스트 아트 샘플 애니메이션
- 상단/중앙: 로고 + 가치 문구
- 메인 CTA: `사진 선택`
- 보조 CTA: `최근 작업`, `설정`
- 상태: 로딩, 오류 alert, 이미지 선택 후 작업공간 이동

### UX 메모
- 버튼 라벨은 설명형 문구를 사용한다.
- 보조 기능은 메인 CTA보다 시각적 우선순위를 낮춘다.

---

## 3.2 작업공간 화면 (`TextifyView`)

### 목표
- 원본 확인 → 결과 감상 → 소비 액션까지 한 화면에서 끝낸다.

### 상단
- 작은 원본 썸네일
- 현재 옵션 요약(팔레트/폭/반전)
- 필요 시 히스토리/공유 진입

### 중앙
- 가장 큰 영역은 결과 프리뷰
- 배경은 터미널/모노스페이스 감성을 살리되 가독성을 우선
- 성공 상태에서는 텍스트 선택 가능
- 더블 탭 포커스 모드 유지
- pinch 확대/축소 유지

### 하단 액션 바
- `복사`
- `공유`
- `저장`
- `옵션`

### 옵션 시트
- 팔레트 선택
- 출력 폭 슬라이더
- 밝기 반전 토글
- 글자 크기 보조 조절

### 피드백
- 복사/저장 성공 시 짧은 배지/토스트
- 생성 실패 시 즉시 재시도 버튼

---

## 3.3 히스토리 화면 (`HistoryView`)

### 목표
- 최근 생성 결과를 다시 찾아볼 수 있게 한다.

### 구성
- 비어 있음 상태
- 카드 리스트
- 상세 보기
- 전체 삭제

### UX 메모
- 메인 작업을 방해하지 않도록 시트/보조 진입으로 둔다.

---

## 3.4 설정 화면 (`SettingsView`)

### 목표
- 제품 사용성에 영향이 있는 최소 설정만 제공한다.

### 구성
- 외형 모드
- 앱 버전/링크
- 히스토리 삭제

---

## 4. 상태 설계

### 런치 화면 상태
- 기본
- 이미지 로딩 중
- 이미지 로딩 실패

### 작업공간 상태
- 초기 생성 중
- 결과 표시
- 재생성 중
- 생성 실패

### 히스토리 상태
- 로딩 중
- 비어 있음
- 목록 표시
- 삭제 실패

---

## 5. 인터랙션 규칙

- 사진 선택 직후 자동 생성
- 폭 슬라이더는 throttle/debounce로 반영
- 팔레트 선택은 즉시 반응하지만 과도한 재생성은 방지
- 복사/저장은 성공 피드백을 보여준다
- 작업공간에서 이탈하지 않아도 주요 작업을 끝낼 수 있어야 한다

---

## 6. 접근성 기준

- 버튼/아이콘에 명확한 라벨 부여
- Dynamic Type에서 주요 CTA가 깨지지 않도록 레이아웃 유지
- 텍스트 결과 영역은 선택 가능하고 충분한 대비를 유지
- 로딩/에러/성공 피드백은 텍스트로도 인지 가능해야 함

---

## 7. 구현 우선순위

3. 옵션 시트 단순화
4. 히스토리/설정 연결
5. 성공 피드백 및 저장 플로우 연결
