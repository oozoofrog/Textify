# Textify - 제품 기획서

- 작성일: 2026-03-13
- 문서 목적: Textify를 **사진을 ASCII/유니코드 문자열 패턴의 그림으로 변환하는 앱**으로 다시 정의하고, 제품 범위와 MVP 기준을 고정한다.
- 제품 정의: **OCR 앱이 아니라 텍스트 아트 생성 앱**이다.

---

## 1. 제품 한 줄 정의

**Textify는 사진 한 장을 복사·공유 가능한 ASCII 문자열 패턴 그림으로 빠르게 바꿔주는 iPhone 앱이다.**

---

## 2. 문제 정의

사용자는 사진을 일반 이미지가 아니라 **텍스트 기반 결과물**로 바꿔서 다음처럼 쓰고 싶다.

- 메신저/SNS에 독특한 텍스트 콘텐츠로 공유
- README, 프로필, 소개글, 커뮤니티 게시물에 삽입
- 레트로/터미널 감성의 시각 결과물 생성
- 여러 문자 팔레트를 비교하며 가장 마음에 드는 스타일 선택

기존 앱은 코어 엔진은 이미 강하지만, 다음 문제가 있었다.

1. 실제 앱 엔트리와 문서상 플로우가 분리되어 있었다.
2. 결과 생성/복사/저장/히스토리 기능이 한 흐름 안에서 일관되게 연결되지 않았다.
3. 툴바 중심 UI는 기능은 많지만 초보 사용자에게 발견성이 낮았다.
4. 문서와 실제 빌드/테스트/버전 정책이 일부 어긋나 있었다.

---

## 3. 제품 비전

### 3.1 비전
**"가장 빠르게 사진을 텍스트 그림으로 바꾸는 앱"**

### 3.2 핵심 가치
- **즉시성**: 사진 선택 직후 바로 첫 결과를 본다.
- **창의성**: 팔레트/폭/반전 조합으로 다양한 분위기를 만든다.
- **활용성**: 결과를 복사·공유·저장으로 바로 소비한다.
- **감성**: 모노스페이스 결과물 자체가 제품의 미학이 된다.

## 5. MVP 제품 원칙

1. **Default First**  
   기본값만으로도 괜찮은 첫 결과가 나와야 한다.

2. **Result First**  
   설정 설명보다 결과물을 먼저 보여준다.

3. **Advanced on Demand**  
   자주 쓰는 옵션만 전면에 두고, 나머지는 시트/보조 제스처로 제공한다.

4. **One Workspace**  
   생성, 조정, 복사, 저장을 하나의 작업공간에서 끝낸다.

5. **Reuse Before Rebuild**  
   검증된 `TextifyKit` 코어와 기존 서비스/테스트 자산을 최대한 재사용한다.

## 6. MVP 범위

### P0 (이번 구현 범위)
- 사진 라이브러리에서 이미지 선택
- 이미지 → ASCII/유니코드 텍스트 아트 생성
- 기본 팔레트 5종 + 숫자 팔레트
- 출력 폭 조절
- 밝기 반전
- 결과 복사
- 결과 공유
- 결과 이미지 저장
- 히스토리 조회 (복사/저장한 결과 중심)
- 설정(외형 모드, 히스토리 삭제)
- 로딩/성공/실패/재시도 상태

### P1
- 파일에서 이미지 불러오기 메인 플로우 연결
- 결과 비교(원본/여러 팔레트)
- 프리셋 템플릿/추천 팔레트
- 파일에서 이미지 불러오기 메인 플로우 연결
- 결과 비교(원본/여러 팔레트)
- 프리셋 템플릿/추천 팔레트

### 이번 단계에서 제외
- 비디오 → 텍스트 아트
- 위젯/공유 익스텐션
- 계정/클라우드 동기화
- 서버 연동 기능

## 7. 핵심 기능 명세

### 7.1 생성 기능
| 기능 | 설명 | 기본값 |
|---|---|---|
| 팔레트 선택 | 결과물에 사용할 문자 세트 | 기본 |
| 출력 폭 | 줄당 문자 수 | 80 |
| 밝기 반전 | 밝기 맵핑 반전 | Off |
| 실시간 미리보기 성격의 재생성 | 슬라이더/토글 변경 시 빠르게 반영 | On |

### 7.2 결과 소비 기능
| 기능 | 설명 |
|---|---|
| 복사 | 결과 문자열 전체를 클립보드에 복사 |
| 공유 | 텍스트 자체를 시스템 공유 시트로 전달 |
| 저장 | 렌더링된 이미지로 사진 앱에 저장 |
| 히스토리 | 복사/저장한 최근 결과를 다시 확인 |

### 7.3 팔레트 프리셋
- 기본: `@%#*+=-:. `
- 블록: `█▓▒░ `
- 미니멀: `@. `
- 조밀: 풍부한 ASCII 집합
- 점: `●◉○◌ `
- 숫자: `0123456789 `

## 10. 비기능 요구사항

### 기술 기준
- Swift 6 유지
- 최소 iOS 26 유지
- iPhone 우선 경험
- 오프라인 생성 우선

### 성능 목표
- 1080p 이미지 첫 결과: 체감 3초 이내 목표
- 옵션 변경 후 재반영: 500ms 내 체감 목표
- 불필요한 메인 스레드 블로킹 금지

### 품질 기준
- 로딩/성공/실패/빈 상태 명시
- 서비스 직접 접근은 View 밖으로 제한
- 테스트 가능한 상태 전이 설계 유지
- 개인정보 업로드 없음(로컬 처리 우선)
